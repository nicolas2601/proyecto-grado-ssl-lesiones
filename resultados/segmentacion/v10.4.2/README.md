# Unified DINOv2-DPT segmenter, release v10.4.2

Binary skin-lesion segmentation for dermoscopic images and clinical (phone) photographs. Network input 448 px, aspect ratio preserved.

**Status: published, not deployed.** Production keeps the v10.4.1 segmenter, which is about 3 s faster per analysis on the current server (see Compute cost). This release ships the model, its manifest, the API support and the evidence needed to switch when the hardware allows it.

## What changes vs v10.4.1

- Model: DINOv2 ViT-B/14 (frozen) with a DPT decoder, two output classes, 97.2 M parameters. Package `vera_unified_dpt_50_50_protocol_a_v1`, seed 42, picked by the highest joint validation Dice on PH2-val + PAD-UFES-20-val (package manifest, `evidence/package_manifest.json`).
- Preprocessing: letterbox to 448 px keeping the aspect ratio, ImageNet normalisation, zero padding right and bottom. No hair removal.
- Postprocessing: crop the valid region, channel-1 softmax, bilinear upsample (`align_corners=False`) to the original size, threshold 0.5. No morphology.
- API: the backend reads `dermssl.segmenter.v2` manifests next to v1 (`demo/backend/segmenter_letterbox.py`); unknown steps or a different output contract fail closed. API version 10.4.2. The `/api/analyze` payload keeps the same fields.
- Photometry and tone simulation keep their hair exclusion with the v10.4.1 parameters (black-hat kernel 9, threshold 10, at 224 px).

## Results on ISIC 2018 (2594 images)

Both segmenters scored on the same images with the frozen thesis evaluator; each ONNX file runs through its own backend preprocessing (`scripts/release_v10_4_2/eval_pair.py`, `evidence/paired_isic2018_2594.json`, per-image rows in `evidence/paired_isic2018_2594_cases.jsonl.gz`). Mean over images, 95% bootstrap intervals in brackets.

| Segmenter | Dice | IoU | HD95 (px) |
|---|---|---|---|
| v10.4.1 (ResNet34 U-Net, 224 px) | 0.8320 (0.8240 to 0.8394) | 0.7483 | 291.0 |
| v10.4.2 (DINOv2-B + DPT, 448 px) | 0.8477 (0.8416 to 0.8542) | 0.7615 (0.7541 to 0.7692) | 253.7 (238.6 to 269.0) |

- Paired Dice difference: +0.0157 (95% CI +0.0107 to +0.0206).
- Per image the change is mixed: 902 images improve by more than 0.01, 921 drop by more than 0.01, 771 stay within 0.01. The mean gain comes from fewer failures (Dice below 0.2: 1.93% of images with v10.4.1, 1.00% with v10.4.2) and tighter boundaries (lower HD95).
- The v10.4.1 ONNX file reproduces the thesis number of its torch checkpoint (0.8320) on the full set; this is the first full-set evaluation of that ONNX file.
- Whether ISIC 2018 images were used to train the DPT decoder was not verified here; the package states that selection used PH2 and PAD-UFES-20 validation splits only.

Clinical photographs: the package reports Dice 0.743 (95% CI 0.718 to 0.768) on 313 PAD-UFES-20 clinical images (seed 42). Those masks are not in this repository and the number was not re-run. On internet clinical photographs checked by eye, v10.4.1 often traced hair, lips or the nose while v10.4.2 outlined the lesion (`scripts/release_v10_4_2/clinical_overlays.py`; the images are not redistributed).

## Parity of the API with the package reference

101 images (60 ISIC 2018, 41 internet clinical photographs), API `SegmenterService` against the package's standalone `predict_image` (`evidence/parity_backend.json`):

- 94 masks are bit-identical (0 differing pixels).
- 7 return `degenerate_mask`: the lesion covers less than 1% of the photograph and the API's existing minimum-area guard (shared with tone simulation) rejects it. v10.4.1 returned a mask for these images because it drew large, wrong regions.

## How to enable it

1. Build the API image from this release's source (API 10.4.2).
2. Put `segmenter.onnx` (asset `v10.4.2-segmenter.onnx`, renamed) and `segmenter_manifest.json` in the segmenter directory, set `SEGMENTER_MANIFEST_SHA256` to the manifest's SHA256.
3. Give the container at least 3 GB of memory (measured peak of the segmenter alone with full-size photographs: 1.4 GB).

The previous segmenter keeps working with the same image: mount the v10.4.1 directory and its pin to roll back.

## Limitations

- Latency: on the current VPS (2 vCPU) segmentation goes from 0.2 s to 3.2 s p50 (6.0 s p90).
- Small lesions in wide shots (under 1% of the image) get no contour because of the minimum-area guard.
- The fp16 ONNX file (186 MB, asset `v10.4.2-segmenter-fp16.onnx`) is not faster on CPU; it is meant for GPU. It was not evaluated on ISIC 2018 here (the package reports mask Dice >= 0.999 against fp32).
- Not a medical device; research and non-commercial use.
